# 程序设计
## 当前工程
Unity2022.3 + TEngine + HybridCLR + YooAsset + UniTask + Luban。GameSDK已独立，广告流程已有loading/ready与回调隔离能力。实际游戏核心仍为笔画选字，GameManager依赖CorePlayGamePlay、DrawCharacter、GameSlotView和旧答案配置，不能只换UI贴图。
仓库CLAUDE.md提到的tengine-dev技能目录实际缺失，本轮依据现有源码签名与repowiki核查，不虚构已运行该技能。

## 重建后的模块
- RodRules：纯C#抵消计分、总胜利判断、合法分组、点值守恒；不依赖Unity。
- RodSession：持有一局快照，Begin/SelectGroup/PlaceGroup/Reroll/Revive/Skip；随机生成器可恢复且固定算法，UI不能直接改骰面。
- RodProgress：关卡解锁、真实获胜、跳过、首通奖励状态，独立于活动局。
- RodEconomy：钱包及免费/库存/金币/广告优先级；所有收益和消耗归一事务入口。
- RodSaveRepository：序列化、版本校验、双槽持久化；平台存储由接口注入。
- RodAdService：复用RewardedAdFlow，完成回调只通知应用服务，不在UI中直接加币。
- RodLevelRepository：读200关配置候选经正式转表后的版本，开始局时快照固定；不可运行时依赖策划案目录。
- RodTutorial：事件推进步骤；正常流程与引导共用命令，不模拟点击绕过验证。
- RodPresenter/UI：订阅状态变化，渲染分数、按钮、弹窗；所有确认动作交给服务。框架资源加载释放、AddUIEvent/Remove监听遵循现有API。

## 状态机
Home → LoadingRun → AwaitGroup → Resolving → AwaitGroup / Won / Failed。
AwaitGroup可进入广告等待或重投；Failed可进入ReviveSelection → AwaitAd → AwaitGroup，或新run重开；Won可领取倍奖、进下一关或首页。
动画为独立表现状态。真实状态先提交存档，再播放动画；恢复时跳到已确认终态。广告等待、提交中、动画锁期间禁止重复命令。!浮层没有玩法状态，不存计时和位置。

## 命令与事件
输入命令携带runId、actionId以及face/selectedDieIds等数据。应用服务先验证当前phase和资源，再在副本计算结果，写完整快照，成功才替换内存并发布RunChanged/WalletChanged/SettlementReady。
事件只做通知，订阅者不得再发同一份奖励。RewardCommitted唯一入口同时写wallet和claimed；不要沿用旧GameManager“先推进存档、再逐项AddCoin并分别Save”的分步发奖。
随机算法固定版本，使用可保存uint状态，取0—5用拒绝采样避免模偏差；相同state与手中ID顺序产生相同结果。重进不重随机。

## 本轮基础实现与接入边界
本轮会新增算筹纯规则与快照结构、双槽存储及其测试，并接到旧缓存存储适配层，让当前工程也避免单文件直接覆盖。新游戏活动局通过新DTO表达，不复用答案索引。
旧GameManager/UI仍依赖旧CorePlayGamePlay，不能删除整个CorePlay目录后声称工程可运行。第二步需替换IGamePlay接口语义与UI绑定，第三步替换Prefab和配置收集，最后移除旧笔画整条引用链；见清理清单。
现有SDK、资源模块、启动遥测、UI生命周期、音频、语言管理优先复用。旧字形下载、笔画解析、答案命中、字形分片预热和旧文字关卡逐步退役。
不修改通用TEngine框架或自动生成GameProto类来承载新玩法。配置schema调整走源表和生成器，不手改生成表类。

## 字体导出
停止生成Fonts/Level和_Level SDF，不再读TextLevelDataScriptableObject和拼音集合。普通UI字号用同一字体图集；关卡号数字复用普通UI，名称走语言key。额外UI文案收集到统一文本输入，不把200个关卡生成成200套字体。
保留设置面板字体是为了跨语言菜单显示，和关卡字体无关。普通字体与设置字体稳定GUID/材质引用。静态图集必须实际包含所需字形；缺字应导出失败并明确字符，不能声称Dynamic兜底后又强制Static。保留源字体仅编辑器烘焙使用，运行时按包体策略决定。

## 性能与验收
UI重建不全屏重刷：最多9枚骰子和6区，不在Update扫描全部场景。图标和文本分离，广告loading转圈复用；说明3秒计时绑定弹窗生命周期。避免重复预载Prefab、跨局未释放handle、失败弹窗监听叠加。
验证顺序：纯规则／存储单元测试 → 200关数据校验 → 编辑器脚本编译 → TMP烘焙和Prefab无Missing → PC试玩 → 微信启动/广告/切后台真机。只有完成对应层验证才标记完成。
